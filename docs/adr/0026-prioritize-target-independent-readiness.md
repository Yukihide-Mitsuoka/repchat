# ADR-0026: 分析対象非依存の準備完了を製品機能より先にする

| Field | Value |
|-------|-------|
| Status | accepted（2026-09-15、オーナー指示） |
| Date | 2026-09-15 |
| Deciders | repository owner |
| Author | Codex |
| Supersedes / Superseded by | [ADR-0018](0018-govern-adaptive-analysis-memory.md)を含む過去文書の実装順序・開始条件だけを置き換える |

## Context

過去のroadmap、status、要件、ADRには、外部デモ判定を製品実装の開始条件または次の最優先作業とする記述が
残っていた。一方、現在のruntimeには分析対象固有のcode、profile、設定、固定prompt・SQL、期間parser、
識別子補正、指標定義が残っており、未知の分析対象へ設定なしで適用できる製品要件を満たしていない。

対象固有実装が残る状態を製品能力として示すと、顧客が分析対象を追加するたびに開発待ちが発生する事実を
隠すことになる。オーナーは、対象固有処理の削除と対象非依存pipelineの完成を先に行い、過去の外部デモ判定を
明示的な新しい指示なしに参照、調査、更新、優先順位付け、作業提案、または他タスクの開始条件に使わないよう指示した。

## Decision

### D1. 対象非依存の準備完了を最優先にする

[ADR-0025](0025-discover-analysis-contracts-without-source-specific-code.md)に従い、対象固有のcode・設定・既知知識を
削除する。認可済みscopeのschema、metadata、bounded value profileだけから、同じ共通pipelineが分析契約、
計画、SQL、検査、実行、結果形状、可視化を処理する状態を最優先の完了条件とする。

### D2. 未完成の経路をデモで正当化しない

固有処理が残る間は、既知データで動作しても任意schema対応または製品能力と表明しない。未知・非公開相当の
複数schemaを、対象別変更なしに独立レビュー済み参照結果と反復照合するまで品質境界は未確定とする。

### D3. 過去の開始条件を失効させる

roadmap、status、要件、proposed ADRから古い外部デモ判定による優先順位と開始条件を除去する。承認済みADRの
本文は履歴として保持するが、その実装順序・開始条件は本ADRが置き換える。過去文書を新しいオーナー指示と
解釈してはならない。

### D4. 明示指示があるまで外部デモ作業を選ばない

オーナー本人からその都度明示的な指示がない限り、該当作業を参照、調査、更新、優先順位付け、提案、または
他タスクの開始条件として利用しない。AIが需要検証を理由に自動的に復活させてはならない。

## Consequences

**Positive:**

- 新しい分析対象を追加するたびに開発を要求する構造を、デモ前に除去できる。
- 次の担当者が古いroadmapや要件から失効済みの開始条件を復活させることを防ぐ。
- 製品能力の表明を、既知fixtureではなく対象非依存の反復評価へ結び付けられる。

**Negative:**

- 対象非依存pipelineの実装と反復評価が完了するまで、既知データで動くデモを製品完成の証拠にできない。
- 過去の承認済みADR本文には履歴上の開始条件が残るため、statusと本ADRの置換関係を確認する必要がある。

## Follow-ups

1. `docs/development-handoff.md`の固有処理削除計画を、小さいPRに分けて完了する。
2. activeなroadmap、status、要件、proposed ADRへ失効済みの開始条件が再混入しないことを文書検査で保証する。
3. 対象固有処理を全削除した後、未知schemaの反復評価を行う。
