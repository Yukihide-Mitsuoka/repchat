# RepChatデモ — 5分説明

## 最初の30秒

RepChatは、分析担当者がLooker Studioでグラフを一つずつ作る代わりに、**日本語で書いた定期レポートの
要求を、チーム共通の指標定義に従うSQLとページへ変換する**仕組みです。分からない指標を推測で埋めず、
生成した数値を既知の正解と照合してからEvidenceのレポートとして表示します。

既存BIを置き換えること自体が目的ではありません。複数顧客へ同じ種類のレポートを提供する代理店や
ソフトウェアベンダーが、顧客ごとの手作業と担当者依存を減らすことが目的です。

## 5分で見せる順番

| 時間 | 見せるもの | 伝えること |
|---|---|---|
| 0:00–0:50 | 日本語1件から生成するダッシュボード | 具体的な月次分析依頼を、購入KPI、定着・エンゲージメント、ファネル、日次＋7日移動平均、回遊へ分解する |
| 0:50–1:40 | 生成された6つの分析パネル | ネスト集計やウィンドウ関数を含むSQLをパネルごとに生成し、1画面の読順へ配置する |
| 1:40–2:40 | 各分析の「生成プロセス・SQL」「集計データ」タブ | グラフに対応する生成SQL、生成理由、参照値照合、実クエリ結果を同じ分析内で確認する |
| 2:40–3:30 | 指標定義 | 「購入」「ユーザー」などの意味を代理店側で共通化し、顧客間で再利用する |
| 3:30–4:15 | 未定義指標の節 | 分からない語はもっともらしい数値を出さず、定義追加を求める |
| 4:15–5:00 | Looker Studioとの違いと限界 | 価値を確認し、未実装を製品機能として説明しない |

## Looker Studioとの違い

| 観点 | Looker Studioでの一般的な作業 | このデモ |
|---|---|---|
| レポート作成 | データ接続、計算フィールド、グラフを画面で個別設定 | 日本語の要求からSQL・ソース定義・ページを生成 |
| 指標の意味 | レポートや担当者ごとに計算式を持ちやすい | 代理店が共通の指標定義を保守し、生成時に必ず参照 |
| 曖昧な要求 | 作成者がその場で解釈する | 定義へ解決できない語は拒否し、定義追加を求める |
| 検証 | 作成者が目視や別集計で確認 | 生成フロー内で実行し、既知値と機械的に照合 |
| 成果物 | BIサービス内の設定 | 生成ページとソース定義を顧客のGitへ置く設計（ADR-0014） |

## この場で実測していること

- 日本語の15設問について、指標定義と出力形状を使った生成・実行・照合が**2回連続15/15**
- 定義していない3指標は推測せず拒否し、定義済み指標の言い換えと絞り込みは回答
- 12本のBigQueryクエリをEvidenceでmaterializeし、ビルドしたレポートの値が検証済みの値と一致
- 同じシェルへ2種類のデータを差し替え、再ビルドなしで別の値を表示できること

## 混ぜて説明してはいけないこと

このローカルデモは、**本番の認可ゲート、認証、executorを通りません**。したがって、この画面だけを
根拠に「テナント越境不能」とは言いません。テナント境界のfail-closedなSQL変換、認可ゲート、
ライブ配信は別の受入試験で実測済みですが、このデモと同じ経路にまだ統合されていません。

また、2テナント表示ではGA4の`device.category`を擬似テナントとして使い、12クエリ中2件だけを
差し替えています。実顧客のスキーマで非エンジニアが自力運用できるか、チームが用意した設問以外にも
精度が出るかは未測定です。

## 実演コマンド

ADC設定済みのリポジトリルートで実行します。実Vertex AIとBigQueryを使います。対面デモでは
参照値を登録済みの6問から、購入KPI、リピート率、平均エンゲージメント時間、購入ファネル、
日次セッションと7日移動平均、入口から3ページ目までの主要回遊を生成するショーケースを使います。

```bash
make demo PROJECT=kotonoha-bi-dev SHOWCASE=yes
```

Evidenceアプリの取得、依存関係のインストール、生成、照合、materialize、build、ブラウザ起動までを
含みます。詳細は[report-generation spike](../spikes/report-generation/README.md)にあります。
6問版は実Vertex AI・BigQueryで6/6、Vertex AI推定¥1.285、回遊12 edgeのSankey描画、
production build、ブラウザerror/warning 0まで確認済みです。

### 日本語をその場で入力するライブデモ

参加者が入力した日本語から、その場で生成SQLとグラフを表示する場合は次を実行します。

```bash
make demo-live PROJECT=kotonoha-bi-dev
```

起動時に費用を確認した後、`http://127.0.0.1:8765/`を開きます。画面上部で
「ダッシュボード生成」と「単一グラフ生成」を切り替えます。

ダッシュボード生成では、1つの月次ECサイト分析目的をまずVertex AIへ渡し、意思決定、最大3件の仮説、
読者・比較軸など最大3件の確認事項、KPIとグラフ候補、そのパネルが支える判断を構造化して提案します。
確認への回答を反映した再提案後、ユーザーは読者・比較の考え方と4〜6件のパネルを編集できます。
確定時に仕様をhash付きrevisionとしてfreezeし、組織コンテキストrevisionとともに生成物へ表示してから、
別の費用確認を経て初めてSQL生成・BigQuery実行へ進みます。相談中のBigQuery利用料は0円です。
利用できる候補は、実測済みの購入成果、リピート率、平均エンゲージメント、購入ファネル、
日次セッションと7日移動平均、主要回遊の6分析です。
成果KPIを左上、説明用のファネルと時系列を中央、診断用のSankeyを下部へ置きます。各パネル内の
開閉領域から、そのグラフの生成理由、SQL、参照値照合状態、実クエリ結果を確認できます。SQLは
GitHub Light相当の控えめな配色で予約語などを色分けし、改行とスペースインデントを保持します。
KPI・ファネル・時系列・Sankeyは宣言済みの列数と型に一致する場合だけ描画し、不一致は停止します。
2021年1月は登録済み参照SQLでも照合するため、送信前にVertex AI約¥1.2、BigQuery最大240GiB・
約¥228、合計最大約¥230を確認します。これは6件の生成SQLと最大6件の参照SQLがすべて20GiB上限まで
走り、キャッシュが使えない場合の上限目安です。

単一グラフ生成では、1回の送信ごとにVertex AIによるSQL生成、読み取り専用SQL検査、BigQuery実行、
結果形状に応じたBigValue・棒グラフ・折れ線・Sankey・表の描画をEvidence基調の同じ画面で進行表示します。
実行結果は「グラフ」と「取得データ」を切り替えられ、取得データには描画へ渡した列と行をそのまま表示します。
分析対象データは、既存のGA4 ECサイトと、Issue #188の最初の非GA4検証であるBitcoin取引から選べます。
Bitcoinプロファイルは`bigquery-public-data.crypto_bitcoin.transactions`の`outputs ARRAY<STRUCT>`と、その内側の`addresses ARRAY`を二段階で`UNNEST`し、取引ごとの異なる受取アドレス数帯を棒グラフにします。
2024年の月を明示した対応設問だけを受け付け、別dataset参照、月パーティション不一致、100行超を実行前後で
拒否します。基準SQLのBigQuery dry runは約2.91GiB（3,115,504,440 bytes）でした。画面では生成SQLの
揺れを考慮して20GiBをhard limitにし、通常約¥4・最大約¥20を送信前に再確認します。
この経路はまだ実データ結果・独立レビュー済み参照値を照合していないため「既知値未照合」です。公開スキーマ1種類の縦切りであり、任意の未知スキーマ対応やIssue #188完了の証拠にはしません。
問い合わせに書かれた`YYYY年M月`から`_TABLE_SUFFIX`の月初・月末を決めます。公開サンプルの
利用可能範囲は2020年11月〜2021年1月で、範囲外または不正な年月はVertex AI・BigQueryの前に停止します。
登録済みの17設問と完全一致する場合は
参照SQLの値とも照合し、それ以外は「実行済み・既知値未照合」と明示します。未定義指標はSQLを生成せず、
不足している定義を表示します。各質問の送信直前にVertex AI約¥0.2、BigQuery最大40GiB・約¥38、
合計最大約¥39の目安を再確認します。キャンセルした場合はリクエストを送信しません。無料枠やキャッシュが
適用される場合、BigQuery料金は0円になることがあります。費用確認はページ内のダイアログで行い、
「費用を確認して実行」を選んだ場合だけリクエストを送信します。生成の進行状況には、実行前・処理中・完了・
停止・エラーの状態と、SQL生成、安全検査、データ取得、可視化の現在位置を表示します。

この画面もローカルスパイクであり、本番の認証、gate、executor、顧客Git配送を通りません。
Issue #180の対話とrevision freezeを画面で確認する未検証プロトタイプですが、候補パネルは登録済み6件、
組織コンテキストは`demo-org-ec-v1` fixture、buildは同期処理です。本番の任意分析、永続revision、
非同期queue、resume、publication、デザインパートナー評価を満たした製品機能ではありません。
確定済みダッシュボードの下にある「この結果から会議報告案を生成」は、追加の費用確認後に
保存済みの集計bundleだけをVertex AIへ渡します。BigQueryは再実行せず、48 KiBのbundleと
4,096 output tokensで制限した上限目安はVertex AI約¥5、BigQuery 0円です。出力は観測、解釈、
未検証の仮説、推奨アクション、限界を分離し、数値主張へ
panel ID、実行SQL hash、result revisionを付けます。根拠に無い数値、revision不一致、限界欄の
根拠なし数値、48 KiBを超えるbundleはVertex AI送信前または表示前に拒否します。推奨アクションには期待効果、担当、緊急度、次の一歩、成功指標を
表示します。

会議報告は常に「未承認案」で、外部共有前の人間確認が必要です。ローカルプロセスは直近1件の
確定済みbundleだけをメモリーに持ち、新しいbuild開始または再起動で破棄します。承認履歴の永続化、
外部配信、目標値・施策履歴の取得、本番認証は未実装であり、Issue #181の製品受入条件は閉じません。
任意設問のグラフ種別は結果形状から選択します。`source`・`target`・`sessions`の3列契約はSankeyとして
描画し、同じページ種別は各段階で同色、リンクは遷移元から遷移先へのグラデーションで示します。
複数系列など、それ以外の高度な構成は事前に分析仕様を確定するショーケースを使用します。

1問だけ経路確認する場合は`QUESTION='<日本語>'`を指定します。任意の日本語はBigQuery実行と
Evidence描画まで行いますが、登録済みの参照値とは照合せず「実行済み・参照値未照合」と表示します。
17問の回帰測定を再実行するときは`SHOWCASE`と`QUESTION`を省略します。R1〜R15の過去基準は
2回連続15/15で、R16の移動平均とR17の回遊はIssue #178で追加したため、17問全体の再測定は別途記録します。

## 画面に出る2種類のSQL

| 表示 | 実行場所 | 役割 |
|---|---|---|
| BigQueryへ送ったSQL（AI生成・検査済み） | BigQuery | 公開データを集計する。`SELECT *`を実行前に拒否し、必要列だけを明示する。BitcoinプロファイルではGoogleSQL予約語の裸の`hash`だけを`` `hash` ``へ意味を変えずに補正し、その実行SQLを表示する。それ以外は表示時だけ整形し、実行SQLを変更しない |
| Evidenceでの描画用SQL | materialize後のDuckDB層 | BigQuery結果から描画に使う列を明示して読む。BigQueryへは送らない |

この区別を画面内に出すのは、Evidence側の`select ... from ga4.q1`だけを見て、手書きSQLを
描画していると誤認させないためです。どちらのSQLにも`SELECT *`は出力しません。生成SQLは
SELECT列ごとの4スペースインデント、主要句の改行、大文字キーワードを適用したEvidence標準の
コード領域に表示し、長い式は横スクロール・コピーできます。ショーケースでは各分析の
「分析結果」「生成プロセス・SQL」「集計データ」を同じタブセットに置き、グラフ、SQL、実クエリ結果の
対応を記憶させません。

この同居は機能確認デモ専用です。製品版は閲覧者向けのグラフ／表と、権限を持つ分析担当者向けの
SQL・定義・来歴を分離し、選択したグラフから文脈を保って移動する設計をIssue #179で検討します。
この対話・仕様確定・buildはIssue #180のローカル未検証プロトタイプです。根拠付きの会議向け所見はIssue #181です。

## デザインパートナーに聞くこと

1. 今の定期レポートで、同じ指標やグラフを顧客ごとに何度作り直していますか。
2. 指標の意味はどこにあり、担当者が辞めても再現できますか。
3. 未定義の数字を出さない挙動は、手戻りを減らしますか、それとも邪魔ですか。
4. この生成物を土台に、実際の顧客レポートを作れそうですか。足りないものは何ですか。
5. 顧客のGitへ自動で成果物を書き込むための初回権限付与は可能ですか。
6. 相談・分析定義・ダッシュボード生成・読解報告まで日本語で一連提供される場合、
   1ユーザー月額5,000円前後は、削減できる作業時間に見合いますか。
